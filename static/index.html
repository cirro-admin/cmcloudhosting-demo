Static starter

Files served straight from this release by nginx on the CM Cloud static runtime. There is no application process, so there is nothing to start and nothing to crash.

  1. Look at the URL bar — this release is live on your app subdomain with TLS already in front of it.
  2. Push a repository holding your built site. The platform looks for index.html in dist/, build/, out/ or public/, so a Vite or Next export needs no configuration.
  3. Redeploy and watch the swap — the new release goes live and the previous one retires, with a rollback available.
  4. There are no runtime environment variables here. Everything shipped in a static release is public, so secrets must stay out of the bundle.
  5. Need an API or a database? That is a service of its own — add a managed PostgreSQL or Pocketbase Backend service and call it from the browser.
